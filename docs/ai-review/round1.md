## 已核实的关键事实

- 对话联网（`fqaiChat` 创建 `fqaiWebSession` 时）**未传 `block`**，学生姓名不会从检索词删除；体检联网路径有。
- `fqaiWebSearch` 把 `W.question` 前 128 字作为 `ori_question` 原样发给搜索接口，不经 `fqaiWebQuery`。
- `fqaiTake` 先 SELECT 再 INSERT，并发可越过上限；对话最多 9 轮补全只扣 1 次。
- `fq_ai_log`、`fq_ai_page_cache`、搜索缓存无保留期、无清理。
- 仓库测试未调用 `__fqaiModelHook` / `__fqaiWebHook`。

> 更正：Claude 草稿称「检索词在代码层脱敏」——只对体检联网成立，对话联网不成立。

## 第一批（P1–P5）验收要点

- **P1**：对话会话使用与体检相同的 block（姓名、英文名、常用称呼、监护人名，大小写不敏感）；`ori_question` 删除或先过清洗；电话规则先去空格/连字符/`+86`。
- **P2**：上下文按动作裁剪；员工只送该生相关人员；动态与粘贴截断；页脚列出实际外发字段。是否化名（`S1`）由实现方给方案，Claude 审。
- **P3**：对话日志存长度+哈希，不存原文；`fq_ai_log`、`fq_ai_page_cache` 设保留天数并清理；搜索缓存键用清洗后检索词。不动生产数据，清理随正常请求或定时任务进行。
- **P4**：额度单条 SQL 条件更新；单次 run 设轮数/字符上限；全局日调用上限（配置项，0=不限）。
- **P5**：用 `__fqaiModelHook` / `__fqaiWebHook` 加离线测试：白名单键快照、连字符电话、大小写姓名、`ori_question` 不出现、额度并发不超限。不调用付费 API。

## Claude 补充（未被另两方覆盖的点）

- 文书助手默认只给「问题定位 + 修改建议」，整段改写需显式确认并留痕（产品决定）。
- `/api/ai/status` 做轻量探活，主模型失败时降级或明确提示。
- 系统提示词不再内联全部院校清单，改为按需 `find_schools`（降成本）。
- 把逾期风险评分、材料齐备度等确定性规则前移到程序，模型只读非结构化内容。
