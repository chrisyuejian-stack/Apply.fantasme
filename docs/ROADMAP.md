# 从恢复基线继续迭代

## 已完成：可运行基线

保留上传包业务实现和字节证据；可重复构建；本地 HTTPS + SQLite；原包业务测试及新增重启持久化验证；三种工具共用协作规范。

## 下一步：小步恢复可维护性

1. 建立真实需求清单和角色操作验收样例，先选一个业务流程作为首个迭代目标。
2. 按功能给短符号建立名称映射；先分离内置院校/模板数据，再分离认证、数据访问、文书、DIY、AI 路由。每次只搬一块并验证行为。
3. 前端先隔离 API 访问、状态与权限、格式化工具，再拆页面和表单。保留 FQAPP 接口及现有 URL，避免一次重写。
4. 明确 JSON 业务字段和 API 契约，逐步加入 JSDoc/类型检查；不要凭变量名猜字段、删历史兼容逻辑。
5. 在独立 Cloudflare 测试项目验证 D1、Cookie、资源、角色业务、备份恢复及真实 AI。拿到线上数据库备份后再评估数据迁移。

以上是建议顺序，尚未执行功能重构或线上迁移。后续每次交接使用：目标、涉及文件、行为变化、已跑验证、待办/风险。Codex、Claude 和 Antigravity 都以此仓库为唯一代码基线，避免各自维护整包副本。
