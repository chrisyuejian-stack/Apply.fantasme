# M3「主管提醒」界面规格（已获主人确认的效果图 + v1.2 增补）

效果图：`mockups/m3-advisor.png`（顾问）、`mockups/m3-blocked-dialog.png`（遇阻弹窗）、`mockups/m3-supervisor.png`（主管）。`mockups/m3-mockup-generator.cjs` 是生成效果图的脚本，里面有这些卡片用到的**全部 CSS 类与结构**，可直接作为实现起点。数据与交互契约：`docs/integrations/assistant.md`（v1.2）。

## 位置与导航
- 在现有「任务」页（`#/tasks`）顶部加选项卡：**「申请任务」（原有，行为不变）** 与 **「主管提醒」**。顾问和主管可见；文书老师、学生、DIY 不可见。
- 「主管提醒」选项卡角标 = 待办 + 遇阻数；主管端角标显示 **遇阻数**（如「1 遇阻」，为 0 时显示待办数）。
- 左侧导航「任务」角标与工作台计数加上提醒数。
- 未开启 `BOARD_V12_ENABLED` 时（见契约「上线顺序」）：**不显示公开任务板与认领**，其余（指定顾问的提醒、完成、遇阻）照常。

## 卡片（顾问与主管通用）
左侧 4px 色条表示重要性（重要 `#C0392B`、普通 `#D98E2B`、低 `#B9B3C2`）；标题（粗）；备注（灰）；遇阻时显示浅橙块「遇阻：原因」；元信息一行：截止（逾期红色加粗「已逾期 N 天 · 日期」、今天橙色「今天截止」、其他「日期 截止」）、重要性文字、主管端额外「负责：姓名」、「来自主管 · 日期」、已处理时「已完成/已报遇阻 · 已同步给主管」。已完成：整卡 62% 透明、标题划线、右侧「已完成」标签。
- 分组：顾问端「逾期 / 今天 / 本周 / 之后 / 已完成」（空组不显示）；主管端「遇阻 / 逾期 / 进行中 / 近 7 天已完成」。**已取消（`cancelled`）任务两端都不显示。**
- 顾问端已完成只显示近 30 天，主管端近 7 天。

## 顾问端操作
- `open`：右侧两个按钮「遇阻」（描边）、「完成」（主色）。
- `blocked`：只有「完成」；遇阻块保留显示。
- 点「完成」：直接提交（成功后卡片移入「已完成」，toast「已完成，已同步给主管」）。
- 点「遇阻」：弹窗（见 `m3-blocked-dialog.png`）：标题「报告遇阻」、副标题为任务标题、必填文本框「卡在哪里 / 需要什么帮助」（≤500 字，空则不可提交并提示）、说明「提交后会同步给主管……之后仍可点完成」、按钮「取消 / 提交遇阻」。
- **公开任务板**（v1.2，开启开关后）：在「主管提醒」选项卡内、「逾期/今天…」分组之上，增加一个「公开任务板（N）」区块，列出**未被认领**的公开任务，卡片右侧只有「认领」按钮；点击后成功则卡片移到自己的分组；**并发时失败**（已被他人认领）toast「已被某某认领」并刷新。认领后、仍为 `open` 的卡片多一个次要按钮「释放」（放回公开，需确认）；`blocked` 的卡片没有「释放」。

## 主管端操作
- 筛选：顾问下拉（含「未认领公开任务」「全部顾问」）、状态下拉；右侧小字「提醒只能从助理推送；完成与遇阻会自动回到你的待办」。
- **没有任何新建按钮。**
- 每张卡片右侧显示状态标签（待办 / 遇阻 / 已完成）；公开未认领显示「公开 · 待认领」，已认领显示「已被某某认领」。
- `open`/`blocked` 卡片有「改派 / 释放」「删除」（`…` 菜单即可）。改派选择启用的顾问/主管；释放 = 放回公开；**对 `blocked` 任务改派/释放会把状态重置为 `open` 并清空遇阻信息**——执行前确认框要写明。删除 = 软删除（`cancelled`），确认框写明「删除后助理会收到取消通知」。`done` 不显示删除。

## 其他
- 只使用现有设计系统类（`.tabs/.tab/.count/.pill/.btn/.modal`）与效果图里内联的 `.rm-*` 样式（可挪进 `app.css`）；375px 宽度不得横向溢出（跑 `tests/e2e/mobile_overflow.cjs`，并按需要补这个页面）。
- 所有文字用中文，沿用现有 toast（`Ae(...)`）与弹窗（`Oe({...})`）。
- 前端改动只改 `src/client/app/parts/`，再 `npm run build:client`，两边一起提交（见 `docs/CODE_MAP.md`）。
